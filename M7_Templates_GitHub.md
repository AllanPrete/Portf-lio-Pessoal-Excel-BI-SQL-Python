## 8. Guia de Mensagens de Commit

Use este padrão em todos os seus commits. Mensagens claras fazem o histórico
do repositório contar a história do projeto.

### Formato

```
<tipo>: <descrição curta no imperativo>

[corpo opcional — por que a mudança foi necessária]
```

### Tipos

| Tipo | Quando usar | Exemplo |
|---|---|---|
| `feat` | Nova análise, novo arquivo, nova funcionalidade | `feat: adiciona análise de ROE por segmento` |
| `fix` | Correção de erro em código ou dado | `fix: corrige leitura do CSV com encode utf-8-sig` |
| `docs` | Alteração em README, comentários, documentação | `docs: atualiza README com instruções do Colab` |
| `data` | Adição ou atualização de dados | `data: adiciona base IF.data setembro 2025` |
| `refactor` | Reorganização sem mudar resultado | `refactor: extrai limpeza de dados para função` |
| `style` | Formatação, indentação, sem mudar lógica | `style: aplica formatação PEP8 no notebook` |
| `chore` | Tarefas de manutenção (gitignore, deps) | `chore: atualiza .gitignore para excluir venv/` |

### Exemplos reais para este portfólio

```bash
feat: adiciona notebook de análise exploratória IF.data
feat: cria dashboard Power BI com 6 visuais e 5 medidas DAX
feat: implementa automação de relatório por segmento
fix: corrige cálculo de ROE para evitar divisão por zero
docs: escreve README do projeto Python com resultados reais
data: adiciona arquivo SQL com inserção das 50 maiores instituições
refactor: separa limpeza de dados em função reutilizável
chore: adiciona .gitignore para projetos de dados
```
